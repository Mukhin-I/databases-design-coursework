# Assignment 1 — Hospital Database

Учебная работа по проектированию и реализации реляционной базы данных для больничной информационной системы.

## Задачи

### 1. ER Diagram

Разработана Entity-Relationship Diagram для предметной области больницы.

Диаграмма включает сущности:

- Department
- Doctor
- Patient
- Appointment
- Diagnosis
- Procedure

Для всех сущностей определены атрибуты, связи и кардинальности. Использована нотация Chen ER.

### 2. PostgreSQL Database Schema + Data Load

На основе разработанной ER-модели реализована реляционная база данных в PostgreSQL.

В SQL-скрипте реализованы:

- создание базы данных;
- создание таблиц;
- первичные ключи (PRIMARY KEY);
- внешние ключи (FOREIGN KEY);
- ограничения NOT NULL;
- ограничения UNIQUE;
- ограничения CHECK;
- связи между таблицами;
- заполнение таблиц тестовыми данными.

Каждая таблица содержит не менее 10 записей.

### Дизайн-решения

При разработке ER-диаграммы было принято несколько проектных решений:
- Сущность «Диагноз» смоделирована как слабая сущность, зависящая от сущности «Приём», поскольку, как сказано в задании, «каждый диагноз должен быть связан с конкретным приёмом и не может существовать без него». Таким образом, сущность должна быть обозначена двойным прямоугольником.
- Связи «многие ко многим» были реализованы с помощью ассоциативных сущностей.
- Если атрибут содержит несколько значений (например, атрибут «Местоположение» для сущности «Отдел», состоящий из номера корпуса и номера кабинета), он изображается как составной атрибут для лучшей нормализации.

### Допущения

При разработке схемы были сделаны следующие допущения:
- У каждой сущности есть один уникальный идентификатор.
- В каждой сущности атрибут ID является ключевой переменной.
- Одна сущность не может одновременно принадлежать нескольким родительским сущностям.
- Все связи считаются обязательными, если не указано иное.
