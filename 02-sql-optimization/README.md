# Assignment 2 — SQL & Optimization

Учебная работа по написанию сложных SQL-запросов и оптимизации их выполнения в PostgreSQL.

## Задачи

### 1. Database Creation & Population

На основе базы данных из Assignment 1 была реализована SQL-схема больничной информационной системы и выполнена загрузка предоставленных данных.

Скрипт включает:

- создание базы данных;
- создание схемы;
- создание таблиц;
- загрузку данных;
- ограничения целостности.

### 2. SQL Запросы

Разработаны три SQL-запроса для анализа данных.

#### Query 1

Поиск врачей, которые обработали более 20 приёмов, с подсчётом:

- общего количества приёмов;
- завершённых приёмов;
- отменённых приёмов.

Использованы агрегация, `GROUP BY`, `HAVING` и несколько `JOIN`.

#### Query 2

Поиск пациентов, которые посещали врачей как минимум из трёх различных отделений и потратили на процедуры больше среднего значения по всем пациентам.

Запрос использует:

- несколько `JOIN`;
- `COUNT(DISTINCT ...)`;
- агрегацию;
- CTE;
- подзапрос с вычислением среднего значения.

#### Query 3

Поиск приёмов, для которых у пациента было как минимум три более ранних приёма.

Запрос использует self-join таблицы `APPOINTMENT` и сравнение дат.

### 3. Оптимизация

Для оптимизации запросов были разработаны индексы на столбцах, используемых в соединениях, агрегациях и условиях выборки.

Производительность запросов анализировалась с помощью PostgreSQL `EXPLAIN`.

Для каждого запроса выполнено сравнение планов выполнения до и после создания индексов.

### Результаты

Для текущего набора данных PostgreSQL не изменил основные планы выполнения после добавления индексов. Во всех трёх запросах оптимизатор продолжил использовать последовательное сканирование, hash joins и операции агрегации.

Результаты показали, что при обработке значительной части таблиц PostgreSQL может предпочесть последовательное сканирование индексному доступу.
